SIS Project — Checkpoint 1: Text Analyzer

О проекте

Это мой первый проект по Golang для Checkpoint 1.

Я сделал простую программу для анализа текста. Она принимает текст, считает количество слов и символов и сохраняет результат.

Программа написана на Go. Все задачи хранятся в оперативной памяти, без базы данных.

Как работает программа

При запуске программа создаёт несколько задач с разными текстами.

Для каждой задачи она:

Проверяет, что текст не пустой.

Создаёт задачу и присваивает ей уникальный ID.

Сохраняет задачу в памяти.

Считает количество слов и символов.

Сохраняет результат и меняет статус задачи.

Например, для текста Hello Go world программа покажет:

Words: 3
Characters: 14
Status: completed

Слова считаются с помощью strings.Fields, а символы с помощью utf8.RuneCountInString. Это позволяет правильно считать и английские, и русские буквы.

Как запустить

Для запуска нужен установленный Go 1.27.

Открыть терминал в папке проекта и написать:

go run .

Программа обработает три примера текста и выведет результаты в терминал.

Проверка программы

Для запуска тестов:

go test ./...

Для проверки кода:

go vet ./...

Для проверки форматирования:

gofmt -l .

Если тесты прошли успешно, появится ok. Остальные две команды при отсутствии проблем ничего не выводят.

Файлы проекта

main.go — запуск программы и примеры задач.

task.go — основная логика программы: создание задач, обработка текста, статусы и ошибки.

task_test.go — тесты для проверки работы программы.

go.mod — информация о Go-модуле.

Статусы задач

У каждой задачи есть три основных статуса:

Pending → Processing → Completed

Pending — задача создана, но ещё не обработана.

Processing — программа обрабатывает текст.

Completed — задача обработана, результат готов.

Если задача уже завершена, повторно обработать её нельзя.

Если при обработке возникает ошибка, задача возвращается в статус Pending, чтобы можно было попробовать ещё раз.

Обработка ошибок

В программе предусмотрены проверки на ошибки.

Например:

Нельзя создать задачу с пустым текстом или одними пробелами.

Если искать задачу с несуществующим ID, программа вернёт ошибку.

Нельзя повторно обработать уже завершённую задачу.

Что я использовал

В проекте я использовал основные темы, которые мы проходили на занятиях:

struct — для хранения данных задачи и результата.

methods — для создания и обработки задач.

interface — для работы с обработчиком текста.

map — для хранения задач по их ID.

pointers — для работы с задачами и их изменениями.

error — для обработки ошибок.

testing — для автоматической проверки программы.

Тестирование

Я добавил тесты, которые проверяют создание задач, обработку правильного и неправильного текста, подсчёт слов и символов, работу статусов и нескольких задач одновременно.

Также проверяется, что программа правильно реагирует на ошибки.

Итог

В результате получилась небольшая программа, которая создаёт задачи, обрабатывает текст и сохраняет результаты в памяти.

В следующих Checkpoint проект можно будет расширить, добавив параллельную обработку задач и HTTP-интерфейс.
